# Godot — cross-platform games, GDScript or C#

**Checked against live sources on 2026-09-11.** Godot **4.7.2** (2026-08-18), standard and .NET
editions. Godot ships a minor every ~4–6 months and patches in between; anything here older than
one minor is suspect — `orclab:currency-discipline` says re-check, and "Sources" says where.

**Nobody here has shipped a Godot game, and games are not in focus** (direflail, 2026-09-11).
Thin on purpose, like `stack-unity`: verified ground to start from, the game-specific questions
named and left open.

## When this is the stack

direflail's choice, with Unity, for **cross-platform games including mobile** (BACKLOG #4,
2026-09-11); neither preferred yet. Godot is **MIT-licensed, free, no account, no revenue
threshold** — the whole engine is a ~150 MB executable. Smaller ecosystem than Unity; native
Linux editor that is a first-class platform, not a port. Two languages:

- **GDScript** — Godot's own Python-like language; the default and the one every tutorial uses.
  Exports to every platform including web.
- **C#** — the .NET edition. Desktop is solid; **Android and iOS are marked experimental** in
  Godot's own docs, and **web export is not supported** for C# at all. For a mobile game in
  Godot today, GDScript is the lower-risk choice; this is not a decision, it is what the docs say.

## Toolchain, as of 2026-09-11

| Thing | Current | Where it was read |
|---|---|---|
| Godot | 4.7.2, from godotengine.org (Linux x86_64 and arm64 builds); *export templates* for the same version, downloaded once from the editor (Editor → Manage Export Templates) | godotengine.org/download/linux |
| Android prerequisites | OpenJDK 17+; Android SDK **Platform-Tools ≥ 35, Build-Tools 35.0.1, Platform 35**, CMake 3.10.2, **NDK r28b**; set in Editor Settings → Export → Android. **Android exports work from this machine.** | docs: Exporting for Android |

| Headless export | `godot --headless --export-release "<preset name>" <output path>` from the project directory | docs: Exporting projects |

## Project layout — where things live

| Path | What |
|---|---|
| `project.godot` | Project settings, including `application/config/name` and `application/config/version` (a free-form string). |
| `*.tscn`, `*.gd` / `*.cs`, assets | Scenes, scripts, resources — Godot imposes no directory structure. |
| `export_presets.cfg` | Every export preset (Android, iOS, Linux, …) and its options — **safe to commit**. This is where the store-facing values live. |
| `.godot/export_credentials.cfg` | Passwords and keystore secrets split out of the presets — **never commit** (the `.godot/` directory is git-ignored by Godot's default `.gitignore`). |
| Android export preset (`export_presets.cfg`) | `package/unique_name`, `version/code`, `version/name`, `gradle_build/use_gradle_build`, `gradle_build/export_format` (APK/AAB), `gradle_build/target_sdk`, `gradle_build/min_sdk`, `architectures/arm64-v8a`, `keystore/release` (+ `_user`, `_password` — overridable by `GODOT_ANDROID_KEYSTORE_RELEASE_*` env vars, which is how a CI or headless export gets them without the credentials file). |
| iOS export preset | `application/bundle_identifier`, `application/app_store_team_id`, `application/export_method_release`, `application/min_ios_version`, `application/provisioning_profile_uuid_release`, `privacy/*` (below), `privacy/camera_usage_description` etc. |
| `android/build/` (only if *Install Android Build Template* was used) | The Gradle project Godot's gradle build compiles; needed for AAB and for any plugin. |

## Build

Android AAB: enable `gradle_build/use_gradle_build`, set `export_format` to AAB, install the
Android build template once (Project → Install Android Build Template), fill the release keystore,
untick *Export With Debug*, then export — or headless: `godot --headless --export-release
"Android" build/game.aab`. iOS: export the preset to a directory; open the `.xcodeproj` it writes
and archive as the App Store ingredient's local shape describes.

Coverage, mutation testing and test lint for this language: `skills/orc-test/languages/gdscript.md`
— `/orc-test` reads it.

## Where each store rule lands

The store ingredients (`skills/orc-package/ingredients/play`, `.../app-store`) state the rules.

| Rule | Where it lands in Godot | Check |
|---|---|---|
| Play: target API 36 | `gradle_build/target_sdk` in the Android preset. **Godot 4.7's docs still list SDK Platform 35 as the prerequisite; Play has required 36 since 2026-08-31.** Install Platform 36 and set `target_sdk = "36"` explicitly rather than trusting the default. | `grep target_sdk export_presets.cfg`; `bundletool dump manifest --bundle=build/game.aab \| grep targetSdk` |
| Play: 16 KB alignment | Godot ≥ 4.5 engine libraries; any GDExtension with native code must be rebuilt with NDK ≥ r28. | `bundletool dump config --bundle=build/game.aab \| grep alignment` → `PAGE_ALIGNMENT_16K` |
| Play: 64-bit | `architectures/arm64-v8a = true` (default). | preset |
| Play: upload-key signing | `keystore/release`, `keystore/release_user`, `keystore/release_password` — path in the preset, password in `.godot/export_credentials.cfg` or the `GODOT_ANDROID_KEYSTORE_RELEASE_*` env vars. Godot currently requires the key password to equal the store password. | `git check-ignore .godot/export_credentials.cfg` |
| Play: package name; version code increases | `package/unique_name`, `version/code`, `version/name` in the preset. `/orc-version` edits `version/code` and `version/name` (and `application/config/version` in `project.godot` if the project mirrors it). | Play refuses a reused code |
| Play: Data safety | Godot itself sends nothing; a plugin (AdMob, Firebase, analytics) does. Keep the list. | the `addons/` directory and Android plugins |
| App Store: Xcode 26+ | The Mac's Xcode, against the exported project. | `xcodebuild -version` |
| App Store: **privacy manifest** | **Generated** from the preset: `privacy/file_timestamp_access_reasons`, `system_boot_time_access_reasons`, `disk_space_access_reasons`, `active_keyboard_access_reasons`, `user_defaults_access_reasons`, `privacy/tracking_enabled`, `privacy/tracking_domains`, and `privacy/collected_data/<type>/{collected, collection_purposes, linked_to_user, used_for_tracking}` for 36+ data types. Godot writes `PrivacyInfo.xcprivacy` into the exported project; plugins with native code still need their own. | the exported project contains `PrivacyInfo.xcprivacy`; Xcode → Product → *Generate Privacy Report* |
| App Store: bundle id, team, signing, min iOS | `application/bundle_identifier`, `app_store_team_id`, `export_method_release`, `provisioning_profile_uuid_release` (empty = automatic), `min_ios_version`. | preset; the exported project's General tab |
| App Store: build number increases | `application/short_version` and `application/version` in the iOS preset (version string and build number). | App Store Connect refuses a reuse |
| App Store: usage strings | `privacy/camera_usage_description`, `microphone_usage_description`, `photolibrary_usage_description` (+ `_localized`). | exported `Info.plist` |
| Both: privacy policy in-app, account deletion, login rules | Game code. | — |

## What games change — named, not answered

Same open questions as `stack-unity`, same honest state. Godot's mechanism for one game with
different controls per device is the **InputMap** (Project Settings → Input Map): actions
(`jump`, `move_left`) bound to touch, keys and gamepad, queried as actions in code; on-screen
touch controls are `TouchScreenButton` nodes shown only on mobile. Designing input as actions from
day one is what makes a desktop sibling possible; which actions, and whether a desktop build ships
at all, is the game's decision. Desktop distribution is Steam, itch.io, or the Linux channels
Orclab already knows.
